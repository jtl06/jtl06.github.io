SwiftFIX — SIMD FIX pre-parser

C++20 structural scanning for FIX tag-value streams, with scalar and AVX2 paths.

The work before parsing

Before QuickFIX can interpret a message, it has to extract it from an incoming byte stream. Its stock splitter creates a string for each message and moves the remaining buffer on each dequeue. SwiftFIX replaces that allocation and copying with a linear scan into reusable, caller-owned storage. QuickFIX still handles message semantics, session state, and downstream validation.

Frame-splitting throughput

The scalar path already delivers most of the improvement. AVX2 raises throughput further, reaching about 15× the stock splitter on this corpus.

Release build on an Intel Core i7-12650H; 1,190 synthetic FIX messages from corpus/bulk.stream. Bars share a linear scale, with MiB/s converted to GiB/s. CPU frequency scaling was enabled. These measurements cover stream splitting, not end-to-end application throughput.

Keep offsets, reuse the scan

SwiftFIX locates field boundaries, validates the fixed header and body length, and records compact offsets into an output table. Keeping positions in the original bytes avoids repeated string extraction. A QuickFIX integration shim consumes the precomputed field index so parsing can reuse that structural work.

Where SIMD pays off

The AVX2 scanner compares 32 bytes at a time to find SOH delimiters across the message body, then parses tag digits between those known boundaries. Short fixed-header fields stay scalar: their scan is too small to justify SIMD setup. Runtime CPU dispatch selects AVX2 when available, with a scalar fallback.

  • Cycles per message: 3,999 for QuickFIX, 353 for scalar SwiftFIX, and 257 for AVX2.
  • L1 data-cache misses per message: 911 for QuickFIX and 0.35 for AVX2, despite AVX2 executing more instructions.

The hardware counters point to the value of reducing memory traffic alongside vectorizing the scan.
